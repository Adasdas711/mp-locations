# Как работает API PALACE

API нужен для аддонов: программа расширения получает объект `api` в `exports.activate(api)` и через него обращается к редактору. Сейчас версия интерфейсов — `1.4.0`, а в manifest по-прежнему указывается `apiVersion: 1`. Это локальные JavaScript-интерфейсы внутри приложения; сервер или токен для их использования не нужны.

Полная сверенная документация, включая объявленные настройки, точные разрешения, ограничения и рабочий шаблон для другого ИИ: [ADDONS_AI_GUIDE.md](ADDONS_AI_GUIDE.md). Типы SDK: [palace-sdk.d.ts](docs/addons/palace-sdk.d.ts).

## Что происходит при вызове

1. Пользователь устанавливает ZIP / `.palace-addon` с `manifest.json` и `main.js`.
2. Приложение запускает код в отдельном sandbox-iframe и вызывает `activate(api)`.
3. Вызов, например `await api.tour.connect(...)`, передаётся редактору через `postMessage`. Хост проверяет источник, канал, разрешение аддона, параметры и текущий режим.
4. Редактор выполняет действие и возвращает результат либо ошибку. Изменения проекта участвуют в истории отмены, автосохранении и экспорте дворца.

Методы общения с редактором возвращают Promise: используйте `await` и `try/catch`. Регистрация команд, чтение ресурсов пакета и регистрация подписки синхронные. Имена `PalaceAPI.tourConnect` в коде приложения — внутренний адаптер; в аддоне используется `api.tour.connect`.

## Основные интерфейсы

| Область | Что доступно | Разрешения |
| --- | --- | --- |
| `api.project` | Копия метаданных, этажей, локусов и камер; изменение метаданных | `project.read`, `metadata.write` |
| `api.plan` | Этажи, изображения, порядок, совмещение/разделение, стены и поворот | `plan.read`, `plan.write`; выбор этажа — `view.control` |
| `api.markers` | Добавление, изменение, удаление локусов и привязка к камере | `markers.write` |
| `api.tour` | Камеры и панорамные данные, положения, переходы, стартовая камера, выбор и ракурс | `tour.read`, `tour.write`; выбор/ракурс — `view.control` |
| `api.view` | Чтение/переключение плана, 3D, разделённого экрана и масштаба | `view.control` |
| `api.ui` | Сообщения, HTML-панели, команды, темы, видимость инструментов, графические слои | Управление — `ui.control`; слои и кнопки — `ui.contribute` |
| `api.commands` | Регистрация команд, объявленных в manifest | Объявление в `contributes.commands` |
| `api.storage`, `api.assets` | Собственные JSON-настройки и ресурсы установленного пакета | Отдельные разрешения не нужны |

`project.read()` возвращает компактную копию без байтов изображений; `plan.read()` и `tour.read()` могут содержать локальные изображения/панорамы. Изменение возвращенной копии не меняет дворец: нужно вызвать метод записи. Индексы этажей и локусов начинаются с нуля; после перестановки их следует перечитать. ID камеры — ключ объекта, полученного через `tour.read()`.

## Пример: связать две камеры

`manifest.json`:

```json
{
  "id": "my.links",
  "name": "Связать камеры",
  "version": "1.0.0",
  "apiVersion": 1,
  "main": "main.js",
  "permissions": ["tour.read", "tour.write"],
  "contributes": {
    "commands": [{"id": "my.links.connect", "title": "Связать первые две камеры"}]
  }
}
```

`main.js`:

```js
exports.activate = api => {
  api.commands.register('my.links.connect', async () => {
    const cameras = await api.tour.read();
    const [from, to] = Object.keys(cameras);
    if (!from || !to) throw new Error('Нужны две камеры');
    const changed = await api.tour.connect({from, to, add: true});
    await api.ui.showMessage(changed ? 'Камеры связаны' : 'Переход уже есть');
  });
};
```

Переход создаётся сразу в обе стороны; `add: false` удаляет оба направления. `api.tour.setStart(from)` назначает начальную камеру, `setStart(null)` снимает назначение. Запись разрешена в режиме редактирования, вне повторения. Без `tour.write` запрос отклонится на стороне редактора.

## Собственная кнопка и панель

Объявите команду и панель в `contributes.commands` / `contributes.panels`. В командном обработчике вызовите `await api.ui.showPanel('my.links.panel', html)`; ID панели должен быть объявлен и начинаться с ID аддона и точки. Панель работает в iframe: она не получает DOM основного приложения.

Для значка на левой панели добавьте `ui.contribute` и объявление:

```json
"activityBar": [
  {"id": "my.links.activity", "title": "Связать камеры", "icon": "camera", "command": "my.links.connect"}
]
```

Это поле размещается внутри `contributes`. Вместо встроенного имени `camera` можно указать путь к своему SVG/PNG в пакете. Кнопки на других панелях объявляются через `contributes.toolbars`, с `location`: `plan`, `tour`, `header` или `status`.

## Изменения проекта и настройки

`api.onProjectChanged(handler)` доставляет копию проекта после изменений (с небольшой задержкой); требует `project.read` и возвращает `{dispose()}` для отписки. Не записывайте проект безусловно из обработчика каждого изменения — это вызовет цикл уведомлений.

`await api.storage.set('settings', {enabled: true})` сохраняет настройки только данного аддона; `await api.storage.get('settings')` их читает. Для управления видимостью сначала получите `await api.ui.tools()`, затем вызовите `await api.ui.setToolVisible(tool.id, false)` с `ui.control`. Видимость сохраняется в этом браузере.

Полный список параметров, ограничения и сборка пакета: [ADDONS.md](ADDONS.md). Создание/удаление камер и загрузка панорам доступны через `tour.add`, `tour.remove`, `tour.loadPanorama`; файлы архива — через `archive`, свои сочетания — через `keybindings`. Готовые расширения VSCode и Node.js-модули не запускаются — используется собственный формат PALACE и относительные CommonJS-модули пакета.

Для собственных тем и иконок добавлены `api.ui.registerAppearance`, `removeAppearance`, `iconThemes`, `iconTheme`. Пример отдельного расширения: [Темы и иконки](addons/appearance/README.md).

## Что аддонам пока недоступно

- Установка расширений VSCode `.vsix`, пакетов npm, Node.js API, доступ к файловой системе и внешним сетевым сервисам. Можно читать ресурсы собственного пакета и локальные данные, разрешённые API.
- Прямой доступ к DOM редактора и замена его обработчиков. Панель аддона имеет свой DOM в sandbox-iframe; интерфейс редактора изменяется через объявленные кнопки, команды, безопасные слои и оформление.
- Добавление настоящих 3D-мешей, изменение материалов, геометрии и рендера Three.js. Графический слой `tour` — фигуры поверх экрана, а не объекты в 3D-сцене.
- Регистрация собственного движка повторения, типов локусов, формата дворца или новых схем активации. Свои сочетания для объявленных команд можно регистрировать через `api.keybindings`; занятые системные сочетания отклоняются. Команды аддона запускаются из менеджера, поиска команд и объявленных кнопок.
- Произвольный CSS всей страницы и полная SVG-разметка системных иконок. Новое API оформления разрешает проверенные цветовые токены и SVG-пути существующих символов; прочие свойства темы наследуются от встроенной базы.
- Зависимости между аддонами, Marketplace и автоматическое сетевое обновление пакетов. Установка/замена выполняется локально; аддоны не входят в экспорт дворца.

Это ограничения текущей версии `1.4.0`, а не обещание полного доступа к внутренним функциям редактора. Полный перечень доступных методов приведён в [ADDONS_AI_GUIDE.md](ADDONS_AI_GUIDE.md).

API камер, файлов архива и горячих клавиш описан в [ADDONS.md, API 1.3](ADDONS.md#камеры-архив-и-горячие-клавиши-api-13).
